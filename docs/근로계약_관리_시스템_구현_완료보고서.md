## 구현 내용

### 1. 핵심 엔티티 구현

#### 1.1 Contract 엔티티
- **위치**: `backend/src/main/java/com/smartcon/domain/contract/entity/Contract.java`
- **주요 필드**:
  - 노무자 (worker) - User 엔티티 참조
  - 프로젝트 (project) - Project 엔티티 참조
  - 근무일자 (workDate)
  - 공종 (jobType) - AttendanceRecord.JobType enum
  - 단가 (unitPrice) - BigDecimal
  - 계약 상태 (status) - ContractStatus enum
  - 계약서 파일 URL (contractFileUrl) - S3 저장용
  - 전자서명 데이터 (signatureData) - Base64 인코딩
  - 서명 완료 일시 (signedAt)
  - 수정 요청 사항 (modificationRequest)
  - 계약 만료일 (expiryDate)
  - 계약 생성자 (createdBy)

#### 1.2 ContractStatus Enum
- **PENDING**: 서명대기 - 계약서가 생성되어 노무자의 서명을 기다리는 상태
- **SIGNED**: 서명완료 - 노무자가 전자서명을 완료한 상태
- **EXPIRED**: 만료 - 계약 유효기간이 지난 상태
- **CANCELLED**: 취소 - 계약이 취소된 상태

### 3. DTO 구현

#### 3.1 ContractRequest
- 계약 생성 요청 DTO
- 필드: workerId, projectId, workDate, jobType, unitPrice, expiryDate
- Jakarta Validation 적용

#### 3.2 ContractResponse
- 계약 응답 DTO
- Contract 엔티티로부터 변환 메서드 제공 (`from()`)
- 마스킹된 정보 및 표시명 포함

#### 3.3 SignContractRequest
- 계약서 서명 요청 DTO
- 필드: contractId, signatureData (Base64 인코딩)

#### 3.4 ModificationRequest
- 계약 수정 요청 DTO
- 필드: contractId, modificationRequest (최대 1000자)

#### 3.5 ResendContractRequest
- 계약서 재발송 요청 DTO
- 필드: contractId, reason (선택사항)

## 주요 기능

### 1. 계약 생성
- 현장관리자 또는 본사관리자가 노무자에 대한 근로계약 생성
- 근무일자, 공종, 단가 등 계약 정보 입력
- 계약 생성 시 자동으로 PENDING 상태로 설정

### 2. 전자서명
- 노무자가 본인의 계약에 대해 전자서명 수행
- Base64 인코딩된 서명 데이터 검증
- 서명 완료 시 자동으로 SIGNED 상태로 변경
- 서명 데이터 크기 및 형식 검증

### 3. 계약 수정 요청
- 노무자가 계약 내용에 대한 수정 요청 등록
- 수정 요청 사항은 텍스트로 저장 (최대 1000자)
- PENDING 상태의 계약만 수정 요청 가능

### 4. 계약서 재발송
- 계약 생성자 또는 관리자가 계약서 재발송
- PENDING 또는 EXPIRED 상태의 계약만 재발송 가능
- 재발송 시 기존 서명 데이터 및 수정 요청 초기화
- 만료된 계약은 PENDING 상태로 복원

### 5. 계약 취소
- 계약 생성자 또는 관리자가 계약 취소
- 취소된 계약은 CANCELLED 상태로 변경

### 6. 만료 처리
- 배치 작업을 통한 만료된 계약 자동 처리
- 만료일이 지난 계약을 EXPIRED 상태로 변경
