## 2. 재정비된 개발 단계

### Phase 0: 프로토타입 완성 (2주) 🎯 **최우선**
**목표**: 완전한 기능을 가진 프로토타입으로 사용자 피드백 수집

#### 0.1. 프론트엔드 프로토타입 완성 (1주)
- [ ] **인트로 페이지**: ismartcon.net과 동일한 구성으로 구현
  - 상단 메뉴: 비대면바우처, 스마트콘 소개, 핵심기능, 서비스요금, 문의하기, 로그인
  - 문의/데모 신청 폼: 회사명, 담당자, 연락처, 이메일, 문의내용
  - 반응형 디자인: PC 2컬럼, 모바일 1컬럼
- [ ] **인증 플로우**: 로그인 방식 선택 → HQ/소셜 로그인 → 역할 선택
  - 본사 관리자: 사업자번호 + 비밀번호
  - 소셜 로그인: 카카오, 네이버 OAuth2
  - 역할/현장 선택: 다중 역할 지원
- [ ] **역할별 대시보드**: 5개 역할(Super/HQ/Site/Team/Worker) 대시보드
  - 슈퍼관리자: 테넌트 관리, 결제/정산, 시스템 모니터링
  - 본사관리자: 현장관리, 노무자관리, 계약관리, 정산관리, 설정
  - 현장관리자: 출역관리, 작업일보, 계약관리, 팀관리, 급여관리
  - 팀장: 작업요청, 팀원관리, 일보작성, 출역현황
  - 노무자: 출역조회, 계약서, 내정보
- [ ] **핵심 화면 구현**:
  - 현장 관리: 목록, 등록, 수정, 상세보기
  - 사용자 관리: 초대, 승인, 역할 부여
  - 출역 관리: 실시간 현황, 기록 조회, 수동 보정
  - 계약 관리: 계약서 목록, 서명, PDF 다운로드
  - 작업 배정: 요청 생성, 수락/거부, 승인
- [ ] **반응형 디자인**: PC/태블릿/모바일 완전 대응
  - PC: 좌측 사이드바 + 메인 컨텐츠
  - 모바일: 상단 헤더 + 하단 탭바
- [ ] **모든 팝업/모달**: 등록, 수정, 삭제, 상세보기 모달 구현
- [ ] **헤더 기능**: 다국어, 현장변경, 알림 아이콘 및 패널

#### 0.2. 목업 데이터 및 상태관리 (3일)
- [ ] **완전한 목업 데이터**: 실제 데이터처럼 보이는 완전한 샘플 데이터
  - 테넌트: 10개 회사 데이터

  - 사용자: 각 역할별 20-50명

  - 계약서: 다양한 상태의 계약서
- [ ] **Zustand 상태관리**: 사용자, 현장, 출역 등 상태 관리
  - 인증 상태: 로그인, 토큰, 사용자 정보
  - 현장 상태: 선택된 현장, 현장 목록
  - 출역 상태: 실시간 출역 현황
  - UI 상태: 모달, 로딩, 알림
- [ ] **라우팅 완성**: 모든 화면 간 네비게이션 구현
- [ ] **에러 처리**: 404, 권한 없음 등 에러 페이지

#### 0.3. 사용자 테스트 준비 (2일)

- [ ] **피드백 수집**: 피드백 수집 방법 및 도구 준비

### Phase 1: 핵심 인프라 및 인증 (3주)
**목표**: 프로덕션 기반 인프라 및 인증 시스템 구축

#### 1.1. 개발 환경 및 인프라 (1주)
- [ ] **Docker 환경**: MariaDB, Redis, MinIO 컨테이너 구성
  - docker-compose.yml: 개발용 환경 설정
  - 환경 변수: 데이터베이스, Redis, S3 설정
  - 볼륨 마운트: 데이터 영속성 보장
- [ ] **CI/CD 파이프라인**: GitHub Actions 기본 워크플로우
  - 빌드: Maven, npm 빌드 자동화
  - 테스트: 단위 테스트, 통합 테스트 실행
  - 배포: 스테이징, 프로덕션 배포 자동화
- [ ] **환경 설정**: 개발/스테이징/프로덕션 환경 분리
  - application-local.yml: 로컬 개발 설정
  - application-dev.yml: 개발 서버 설정
  - application-prod.yml: 프로덕션 설정
- [ ] **로깅 시스템**: 구조화된 로깅 및 모니터링 설정
  - Logback: JSON 형태 로그 출력
  - 로그 레벨: 환경별 로그 레벨 설정
  - 로그 수집: ELK 스택 또는 클라우드 로깅

#### 1.2. 백엔드 핵심 모듈 (1주)
- [ ] **멀티테넌트 구현**: Hibernate Filter 기반 테넌트 격리
  - TenantContext: ThreadLocal 기반 테넌트 컨텍스트
  - BaseTenantEntity: 모든 엔티티의 기본 클래스
  - TenantFilter: 자동 테넌트 필터링
- [ ] **공통 모듈**: ApiResponse, GlobalExceptionHandler, 감사로그
  - ApiResponse: 표준화된 API 응답 형식
  - GlobalExceptionHandler: 전역 예외 처리
  - AuditLog: 모든 API 호출 로그 기록
- [ ] **보안 설정**: Spring Security + JWT 구현
  - SecurityConfig: 보안 설정 및 필터 체인
  - JwtAuthenticationFilter: JWT 토큰 검증
  - PasswordEncoder: 비밀번호 암호화
- [ ] **데이터베이스**: 핵심 엔티티 및 Repository 구현
  - User, Tenant, Site, Team 엔티티
  - JPA Repository 및 Custom Repository
  - 데이터베이스 마이그레이션 스크립트

#### 1.3. 인증 시스템 (1주)
- [ ] **JWT 인증**: 토큰 생성, 검증, 갱신 로직
  - JwtTokenProvider: 토큰 생성 및 검증
  - RefreshToken: 리프레시 토큰 관리
  - TokenBlacklist: 로그아웃된 토큰 관리
- [ ] **소셜 로그인**: 카카오, 네이버 OAuth2 연동
  - OAuth2UserService: 소셜 로그인 사용자 처리
  - OAuth2SuccessHandler: 로그인 성공 후 처리
  - OAuth2FailureHandler: 로그인 실패 처리
- [ ] **권한 관리**: 역할 기반 접근 제어 (RBAC)
  - @PreAuthorize: 메서드 레벨 권한 검증
  - RoleHierarchy: 역할 계층 구조
  - PermissionEvaluator: 세밀한 권한 검증
- [ ] **API 보안**: 모든 API 엔드포인트 보안 적용
  - CORS 설정: 허용된 도메인만 접근
  - Rate Limiting: API 호출 제한
  - Input Validation: 입력 데이터 검증

- **feature/**: 개별 기능 개발 브랜치 (예: `feature/auth-login`)

- **Conventional Commits** 준수
  - `feat: 새로운 기능 추가`
  - `fix: 버그 수정`
  - `docs: 문서 수정`
  - `refactor: 코드 리팩토링`

- **Dev**: Docker Compose로 로컬/개발 서버 배포
