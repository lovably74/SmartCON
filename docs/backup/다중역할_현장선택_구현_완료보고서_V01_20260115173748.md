# 다중 역할 및 현장 선택 로직 구현 완료 보고서

## 개요
SmartCON Lite 5단계 역할 기반 시스템의 다중 역할 및 현장 선택 로직을 구현하였습니다.
사용자가 여러 역할을 가지고 있거나 여러 현장에 배정된 경우, 적절한 역할과 현장을 선택할 수 있는 기능을 제공합니다.

## 구현 일시
2026년 1월 15일

## 구현 내용

### 1. DTO 클래스 생성

#### UserRoleInfo.java
- 사용자 역할 정보를 담는 DTO
- 역할별 접근 가능한 현장 목록 포함
- 현장 선택 필요 여부 판단 로직 포함

#### SiteInfo.java
- 현장 정보를 담는 DTO
- 현장 ID, 이름, 위치, 상태, 공사 기간 정보 포함
- 남은 공사 일수 자동 계산
- 마지막 접근 시간 및 배정 시간 정보 포함

#### RoleSelectionResponse.java
- 역할 선택 응답 DTO
- 사용 가능한 역할 목록 및 현장 정보 포함
- 역할/현장 선택 필요 여부 판단
- 자동 선택 가능 여부 판단 (단일 역할, 단일 현장인 경우)

#### SiteSelectionRequest.java
- 현장 선택 요청 DTO
- 선택한 역할 및 현장 ID 포함

#### SiteSelectionResponse.java
- 현장 선택 응답 DTO
- 선택된 역할 및 현장 정보 포함
- 새로운 액세스 토큰 및 리프레시 토큰 포함 (향후 JWT 통합 예정)

### 2. Repository 생성

#### ProjectManagerRepository.java
- 프로젝트 관리자 관련 쿼리 메서드 제공
- 사용자 ID로 활성 프로젝트 관리자 목록 조회
- 사용자 ID와 역할로 활성 프로젝트 관리자 목록 조회
- 사용자의 프로젝트 접근 권한 확인
- 프로젝트 수 조회

### 3. Service 구현

#### RoleSelectionService 인터페이스
- 역할 및 현장 선택 관련 비즈니스 로직 정의
- 사용 가능한 역할 및 현장 목록 조회
- 역할별 현장 목록 조회
- 역할 및 현장 선택 처리
- 접근 권한 검증
- 현장 접근 시간 업데이트

#### RoleSelectionServiceImpl 구현
- 다중 역할 처리 로직 구현
- 역할별 현장 접근 권한 로직 구현:
  - **슈퍼관리자**: 모든 테넌트의 모든 현장 접근 가능
  - **본사관리자**: 자신의 테넌트 내 모든 현장 접근 가능
  - **현장관리자/팀장**: 배정된 현장만 접근 가능
  - **일반노무자**: 소속된 현장만 접근 가능
- 현장 목록 정렬 로직:
  1. 최근 접근 시간 (최근이 우선)
  2. 최근 배정 시간 (최근이 우선)
  3. 남은 공사 기간 (적게 남은 것이 우선)
- 역할 및 현장 선택 시 접근 권한 검증
- 현장 접근 시간 자동 업데이트

### 4. API Controller 생성

#### RoleSelectionController.java
- REST API 엔드포인트 제공:
  - `GET /api/v1/users/{userId}/roles-and-sites`: 역할 및 현장 목록 조회
  - `GET /api/v1/users/{userId}/sites?role={role}`: 역할별 현장 목록 조회
  - `POST /api/v1/users/{userId}/select-role-and-site`: 역할 및 현장 선택
  - `GET /api/v1/users/{userId}/validate-access`: 접근 권한 검증

### 5. 기존 코드 수정

#### ProjectRepository.java
- tenantId 타입을 String에서 Long으로 변경
- 모든 쿼리 메서드의 파라미터 타입 수정

### 6. 테스트 코드 작성

#### RoleSelectionServiceTest.java
- 12개의 단위 테스트 작성
- 다중 역할 처리 테스트
- 단일 역할/현장 자동 선택 테스트
- 역할별 현장 목록 조회 테스트
- 역할 및 현장 선택 성공/실패 테스트
- 접근 권한 검증 테스트
- 현장 접근 시간 업데이트 테스트
- 예외 처리 테스트

## 주요 기능

### 1. 다중 역할 지원
- 사용자가 여러 역할을 가질 수 있음
- 역할별로 접근 가능한 현장 목록 제공
- 역할 레벨 순으로 정렬 (낮은 레벨이 높은 권한)

### 2. 현장별 역할 매핑
- 사용자가 현장별로 다른 역할을 가질 수 있음
- ProjectManager 엔티티를 통한 현장-사용자-역할 매핑
- 현장별 마지막 접근 시간 추적

### 3. 역할별 현장 접근 권한
- 계층적 권한 구조 적용
- 슈퍼관리자 > 본사관리자 > 현장관리자 > 팀장 > 일반노무자
- 역할에 따라 접근 가능한 현장 범위 제한

### 4. 현장 목록 정렬
- 최근 접근한 현장 우선 표시
- 최근 배정된 현장 우선 표시
- 공사 종료일이 가까운 현장 우선 표시

### 5. 자동 선택 기능
- 단일 역할, 단일 현장인 경우 자동 선택 가능
- 사용자 경험 개선

## 향후 작업

### 1. JWT 토큰 통합
- 현재는 임시 토큰 문자열 반환
- JWT 토큰에 역할 및 현장 정보 포함 필요
- JwtTokenProvider 구현 및 통합

### 2. 노무자-현장 관계 테이블
- 현재는 ProjectManager 테이블 사용
- 일반노무자를 위한 별도 관계 테이블 필요
- Worker-Project 매핑 테이블 구현

### 3. 프론트엔드 통합
- 역할 선택 UI 컴포넌트 구현
- 현장 선택 UI 컴포넌트 구현
- API 연동 및 상태 관리

### 4. 캐싱 최적화
- 역할 및 현장 목록 조회 결과 캐싱
- Redis를 활용한 성능 최적화
